# 4.9 Sagas

**Time:** 15 minutes · **Code:** [`shop/workflows.ts`](../shop/workflows.ts) (`orderSaga`)

The saga pattern is the same in Temporal as in Restate (lesson 3.10): remember how to undo each completed step, and when a later step fails for good, undo in reverse.

```ts
export async function orderSaga(order: Order) {
  const compensations: Array<() => Promise<unknown>> = [];
  try {
    await acts.reserveInventory(order.orderId, order.sku);
    compensations.push(() => acts.releaseInventory(order.orderId, order.sku));

    await acts.chargeCard(order.orderId, order.amountCents);
    compensations.push(() => acts.refund(order.orderId, order.amountCents));

    await acts.shipOrder(order.orderId, order.address);   // ← non-retryable: address rejected
    return { orderId: order.orderId, status: "shipped" };
  } catch (err) {
    for (const undo of compensations.reverse()) await undo();
    throw ApplicationFailure.nonRetryable(`Order ${order.orderId} failed and was rolled back`, "OrderFailed");
  }
}
```

## Differences from the Restate version

| | Restate | Temporal |
| --- | --- | --- |
| What reaches the `catch` | Only `TerminalError` (others are retried *inside* `ctx.run`) | An `ActivityFailure`, once the activity's retry policy gives up or the error is non-retryable |
| With default retries | Transient errors never reach the `catch` | Same: unlimited retries mean only non-retryable failures (or cancellation) reach it |
| Re-throwing at the end | `TerminalError` fails the invocation | Must be an `ApplicationFailure` to **fail** the workflow. A plain `Error` would fail the *workflow task* and retry forever (lesson 4.5). |

That last row trips people up. Rethrowing the original `ActivityFailure` would also fail the workflow. Wrapping it in a clear `ApplicationFailure` gives whoever reads the failure a better message.

> **🎧 Support angle**
> Sagas raise the same question on both platforms: "does it roll back automatically?" No: the platform guarantees your compensations run reliably, and you write them. Ask whether each completed step registered its undo, and whether the failing step's error actually reaches the `catch`.
