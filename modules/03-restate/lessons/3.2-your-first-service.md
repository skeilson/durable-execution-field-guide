# 3.2 Your first service

**Time:** 25 minutes · **Code:** [`shop/greeter.ts`](../shop/greeter.ts)

## The code

```ts
import * as restate from "@restatedev/restate-sdk";

export const greeter = restate.service({
  name: "Greeter",
  handlers: {
    greet: async (ctx: restate.Context, name: string) => {
      return `Hello, ${name}!`;
    },
  },
});
```

A **service** named `Greeter` with one **handler**, `greet`. Every handler gets `ctx` first, then one input. Whatever it returns goes back to the caller.

[`shop/app.ts`](../shop/app.ts) serves all the shop's services from one process:

```ts
await restate.serve({ services: [greeter, orders, payments, /* … */], port: 9080 });
```

## Run it by hand

This is the setup you'll use for the rest of the course. Open **three terminals** in the project folder.

**Terminal 1: the Restate server.** Leave it running.

```bash
npm run restate
```

**Terminal 2: the shop.** Leave it running too.

```bash
npm run shop
```

**Terminal 3: tell Restate where the shop is.** This is called **registering a deployment**. Restate asks the service which handlers it has ("discovery") and starts routing requests to it.

```bash
npm run register
```

Now call the handler, **through Restate** (port 8080), not the service directly:

```bash
curl localhost:8080/Greeter/greet --json '"Dana"'
```

You should get `Hello, Dana!`.

The URL pattern is `http://<restate>:8080/<Service>/<handler>`. The body is the handler's input, as JSON (so a plain string needs quotes inside the quotes).

## What Restate recorded

```bash
npx restate invocations list --all
npx restate services list
```

Your request became an **invocation** with an id like `inv_1aw7CG…`, even though it took a millisecond and did nothing durable. Every request through Restate is recorded and can be looked up afterwards.

## Things that go wrong here

| Symptom | Cause |
| --- | --- |
| `curl: (7) Failed to connect to localhost port 8080` | The Restate server isn't running |
| HTTP 404 `service 'Greeter' not found` | The deployment isn't registered (or you registered a different URL) |
| `register` fails with "connection refused" | The service isn't running on 9080 |
| Changed the code, but Restate still runs the old version | Re-register. During development, `--force` replaces the old registration (our `npm run register` includes it). Module 7 explains why production works differently. |

> **🎧 Support angle**
> "Service not found" right after setup is the first ticket many customers file. The fix is almost always registration: wrong URL, wrong port, or a URL Restate can't reach (common when Restate runs in Docker and the service runs on the host). `restate deployments list` shows what's registered.
