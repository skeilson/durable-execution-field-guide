# 5.3 Architecture and operations

**Time:** 25 minutes

## How failures look

The same failure, seen from each platform. This table is the most useful thing in this module for support work.

| Failure | Restate shows | Temporal shows |
| --- | --- | --- |
| Your code is down | `backing-off`, "connection refused", retry counts | `Running`, pending tasks, no pollers on the task queue, **no error** |
| A step keeps failing | `backing-off` with the last error and stack trace; `paused` after max attempts | Pending activity with attempt count and last failure, retrying (unlimited by default) |
| Permanent failure | `TerminalError` → completed with failure | Non-retryable `ApplicationFailure` → workflow Failed |
| Bug in orchestration code | Retried like any error; invocation backs off | `WorkflowTaskFailed` repeating; workflow stays Running |
| Code changed under a running process | RT0016 journal mismatch (only if the deployment was overwritten) | Non-determinism error, `WorkflowTaskFailed` |
| Waiting for a timer or event | `suspended` (and what it's waiting on) | `Running`, with a timer or no pending task |
| Hot key / busy entity | `pending` invocations behind a running one on the key | Messages queued behind a long-running handler in the workflow |

## Running it

| | Restate | Temporal |
| --- | --- | --- |
| Server | One binary; single node or cluster | Multiple services + database (+ optional Elasticsearch) |
| Local development | `npx @restatedev/restate-server` or Docker | `temporal server start-dev` |
| Your code | HTTP services or serverless functions, registered as deployments | Worker processes polling task queues |
| Network | Restate must reach your services | Workers must reach Temporal (outbound only) |
| Scaling your code | Like any HTTP service | Add workers |
| Versioning | Immutable deployments, pinning | Patching, Worker Versioning |
| History growth | Per-invocation journals; object state kept separately | Per-execution histories with limits: continue-as-new |
| Inspection | CLI, UI, **SQL over internal tables** | CLI, Web UI, visibility queries |

## Two questions to ask every customer

1. **Restate:** "Is your service reachable from Restate, and is it registered?" covers a large share of "nothing works" tickets.
2. **Temporal:** "Is a worker polling that task queue, in that namespace?" covers the same share on the other side.
