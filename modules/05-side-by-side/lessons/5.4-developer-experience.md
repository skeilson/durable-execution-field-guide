# 5.4 Developer experience

**Time:** 15 minutes

These are judgments, not facts. Use this lesson as a starting point and form your own opinions from Modules 3 and 4. What *you* noticed while doing the labs is worth more than any comparison page.

| Topic | Restate | Temporal |
| --- | --- | --- |
| Getting started | `npm install` brings the server; one service file, register, call with `curl` | Install the CLI; write workflows, activities and a worker; start via CLI or client |
| Reading the code | Close to ordinary code: steps inline with `ctx` | Clear separation: orchestration in workflows, side effects in activities |
| Guard rails | Deterministic helpers on `ctx`; nothing stops a side effect outside `ctx.run` | The sandbox blocks I/O and makes time/randomness safe; violations surface early |
| Required configuration | Defaults for timeouts and retries | Activity timeouts required on every proxy |
| State | Built in (virtual objects) | Workflow variables; entity workflows for long-lived state |
| Testing | Run against a local server | Rich testing tools: time-skipping test server, replay tests |
| Ecosystem | Younger; SDKs for TypeScript, Java/Kotlin, Python, Go, Rust | Larger community and many more years in production; SDKs for Go, Java, TypeScript, Python, .NET, PHP, Ruby |
| Debugging | Journal + SQL + UI | Event history + Web UI timeline + stack trace view |
