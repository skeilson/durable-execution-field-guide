# 5.1 One concept map, two vocabularies

**Time:** 20 minutes

You've built the same shop three times: on your mini engine, on Restate and on Temporal. Underneath the different names, they're doing the same things. This map is worth memorizing: half of support work in this space is translating between a customer's words and the product's.

| Concept (Module 2) | Mini engine | Restate | Temporal |
| --- | --- | --- | --- |
| The recorded progress | Journal | Journal | Event history |
| One run of a process | Workflow run | Invocation (`inv_…`) | Workflow execution (workflow id + run id) |
| Durable side effect | `ctx.step` | `ctx.run(…)` | Activity |
| Orchestration code | The workflow function | The handler | The workflow function |
| Durable timer | `ctx.sleep` | `ctx.sleep` | `sleep`, `condition(…, timeout)` |
| Deterministic randomness/time | `ctx.random`, `ctx.now` | `ctx.rand`, `ctx.date` | Automatic in the sandbox |
| Permanent failure | `PermanentError` | `TerminalError` | `ApplicationFailure.nonRetryable` |
| Waiting without running | (no) | Suspension | Workflow not occupying a worker |
| Calling another process | (no) | Service call / send | Child workflow, or activity that starts one |
| Per-entity state | (no) | Virtual object | Entity workflow |
| Run once per id | (no) | Workflow (`run`) | Workflow id uniqueness |
| Event from outside | (no) | Durable promise, awakeable | Signal, update, async activity completion |
| Read state while running | (no) | Shared handler | Query |

## The two architectural differences that matter most

**1. Push vs. pull.** Restate calls your services; Temporal's workers poll for work. This decides how outages look (loud errors vs. silent queues), how you deploy (any HTTP endpoint or serverless function vs. long-running workers), and what networking is needed.

**2. Where side effects live.** Restate puts them *inline* (`ctx.run` blocks inside one handler). Temporal puts them in *separate functions* (activities), called from a sandboxed workflow. Restate code reads like ordinary code; Temporal's separation makes the boundary between orchestration and side effects explicit and enforced.

## Quick translation practice

A Temporal user asks: "How do I signal a running workflow in Restate?"
→ Call a handler on the workflow (or object) that resolves a **durable promise** the `run` handler is awaiting, or resolve an **awakeable**.

A Restate user asks: "What's Temporal's version of a virtual object?"
→ An **entity workflow**: one long-running workflow per key, with signals/updates to change it and queries to read it, and continue-as-new to keep its history short.
