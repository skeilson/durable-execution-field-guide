# 7.6 Security

**Time:** 20 minutes

## What needs protecting

| Surface | Risk | Restate | Temporal |
| --- | --- | --- | --- |
| **Who can call your code** | Someone other than the platform invokes handlers | Services can require **request identity** signatures, so only your Restate server can call them (`withIdentityV1(publicKey)` in the SDK). In development, the SDK warns when this is off. | Workers make outbound connections; nothing calls them |
| **Who can start work** | Unauthorized clients start or signal workflows | Ingress (port 8080) behind your own auth/API gateway; handlers can be marked **private** (`ingressPrivate`), callable only from other handlers | Client authentication: mTLS or API keys (Temporal Cloud), authorizers on self-hosted clusters |
| **Who can administer** | Someone cancels, kills or inspects invocations | Restrict the admin API (port 9070) to operators | Namespace permissions, role-based access in Cloud |
| **Data at rest** | Journals and histories contain your inputs, outputs and state | Platform storage encryption; keep secrets out of journaled values | **Data Converter / Payload Codec** encrypts payloads client-side; a **Codec Server** lets the Web UI decrypt for authorized users |
| **Secrets** | API keys in workflow inputs or step results end up in the journal | Read secrets inside `ctx.run` from a secret store; don't return them | Same, inside activities |

## The journal remembers everything

Anything passed into a handler, returned from a step, or stored in state is written down durably, and visible to anyone who can read journals or histories (the CLI, the UI, SQL). That's exactly what makes support possible, and it's why sensitive data needs deliberate handling.

> **🎧 Support angle**
> Security questions often come from a customer's security review during evaluation. Know these basics well enough to answer confidently and know when to bring in an engineer. When you ask customers to share journals or histories for debugging, remember they may contain personal or payment data: use the customer's approved channel and handle it accordingly.
