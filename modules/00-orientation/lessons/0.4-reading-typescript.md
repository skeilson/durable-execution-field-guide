# 0.4 Reading code (just enough)

**Time:** 20 minutes

You won't be asked to write code from scratch. You will be asked to **read** short programs and change a line or two. This lesson covers everything you need to do that. All the code in this course is **TypeScript**, the most common language for both Restate and Temporal examples.

## Comments are for you

```ts
// Two slashes: everything after this on the line is a note for humans.

/**
 * Slash-star blocks are longer notes. Every file in this course starts
 * with one explaining what the file is for. Read those first.
 */
```

## Values and names

```ts
const orderId = "order-1001";   // a name ("orderId") for a piece of text
const amountCents = 4999;       // a number: $49.99, stored in cents
const order = {                 // an object: several named values bundled together
  orderId: "order-1001",
  amountCents: 4999,
};
order.amountCents               // reach inside an object with a dot → 4999
```

`const` means "this name always refers to this value." You'll also see `let`, which can change.

## Functions: named chunks of work

```ts
function greet(name: string) {
  return "Hello, " + name;
}
greet("Dana");   // → "Hello, Dana"
```

`name: string` says the function expects text. Those `: something` labels are the "Type" in TypeScript. You can mostly ignore them while reading.

You'll also see this shorter style, called an **arrow function**. It means the same thing:

```ts
const greet = (name: string) => "Hello, " + name;
```

## `async` and `await`: waiting for the outside world

Charging a card or calling another service takes time. Code that waits for something like that is marked `async`, and each place it waits says `await`:

```ts
async function checkout() {
  await inventory.reserve("order-1", "SKU-42");   // wait for the warehouse to answer
  await bank.charge("order-1", 4999);             // then wait for the bank
  await shipping.ship("order-1", "123 Main St");  // then wait for shipping
}
```

Read `await` as **"do this, and wait until it's finished before the next line."** That gives you the most important idea in this course: **a program is a list of steps, done in order, each one waiting on something outside.**

## Errors

When something goes wrong, code **throws** an error. Other code can **catch** it:

```ts
try {
  await bank.charge("order-1", 4999);
} catch (err) {
  console.log("The charge failed: " + err.message);
}
```

`console.log(...)` just prints a line in the terminal.

## The pattern you'll see everywhere

Here's a real snippet from Module 3. With the above, you can read it:

```ts
const paymentId = await ctx.run("charge card", () =>
  bank.charge(order.orderId, order.amountCents),
);
```

"Run a step called *charge card*. The step is: charge this order's amount at the bank. Wait for it to finish, and call the result `paymentId`." `ctx` is the durable execution engine. Module 2 explains what it's doing behind the scenes.

## Imports

The top of every file has lines like:

```ts
import { bank, inventory } from "../../shared/fake-world.js";
```

That means "use `bank` and `inventory`, which are defined in another file." `../` means "go up one folder." If you're curious what something does, the import line tells you which file to open.

> **Quick check:** in the checkout example above, if `bank.charge` throws an error, does `shipping.ship` run? *(No: an error stops the function at that line, unless something catches it.)*
