# 0.3 Terminal survival guide

**Time:** 15 minutes

The terminal is a window where you type commands instead of clicking. You only need a handful of them for this course, and support engineers use exactly these every day.

## Where am I, and what's here?

```bash
pwd                 # "print working directory": which folder am I in?
ls                  # list what's in this folder
cd modules          # go into the "modules" folder
cd ..               # go back up one folder
cd ~/durable-execution-field-guide   # jump straight to the project (~ means your home folder)
```

Almost every command in this course must be run from the **project folder**, the one containing `package.json`. If a command says `Missing script` or `no such file`, run `pwd` and check you're there.

## Running the course's commands

All course commands start with `npm run`:

```bash
npm run m1          # run Module 1's demo
npm run m2 -- 2.3   # run Module 2, lesson 2.3 only
```

The `--` passes whatever follows (`2.3`) to the lesson program.

## Stopping things

| Keys | What it does |
| --- | --- |
| `Ctrl` + `C` | Stop whatever is running in this terminal. You'll use this a lot, including to **crash services on purpose**. |
| `↑` (up arrow) | Bring back the last command, so you don't have to retype it |
| `Tab` | Auto-complete a file or folder name |

## Several terminals at once

From Module 3 onward you'll run a server in one terminal, a service in another, and send commands from a third, which is exactly how real systems are debugged.

- **macOS Terminal:** `Cmd` + `T` opens a new tab. `cd` into the project folder in each one.
- **VS Code:** *Terminal → New Terminal*, then the split button to see two side by side.

A tip: give each tab a job and keep it there. "Tab 1 is the server, tab 2 is the service, tab 3 is me."

## Reading command output

Programs print a lot. You don't need to read everything. Look for:

- the **last few lines**, which usually say whether it worked
- the words **error**, **failed**, **refused**, **timeout**
- **ids** (like `inv_17SneV…`), which you'll copy into the next command

> **🎧 Support angle**
> Customers will paste terminal output into tickets. The skill of skimming for the one line that matters is half of support work, and you'll practice it all course long.
